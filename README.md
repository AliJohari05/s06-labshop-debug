# تمرین سر کلاس جلسه‌ی ۶: دیباگ گزارش فروش LabShop

LabShop یه فروشگاه اینترنتی کوچیکه. هر شب یه برنامه سفارش‌های روز رو از `data/orders.csv` می‌خونه و گزارش فروش چاپ می‌کنه. همین برنامه به چهار زبان نوشته شده (`python/`، `java/`، `csharp/`، `go/`) و هر چهار نسخه دقیقاً یه رفتار و یه باگ‌ها رو دارن.

**یکی از زبان‌ها رو انتخاب کنید** (بهتره زبان سرویس تیمتون) و فقط با همون کار کنید.

**زمان: یک ساعت.** سه باگ اجباری‌ان (BUG-1، BUG-2، BUG-4) و هر کدوم یه ابزار رو تمرین می‌ده. BUG-3 اختیاریه، برای وقتی که زودتر تموم کردید.

| زمان پیشنهادی | کار |
|---|---|
| ۵ دقیقه | شروع و اجرای برنامه |
| ۱۰ دقیقه | BUG-1 با Stack Trace |

## شروع

1. بالای صفحه **Fork** کنید و از Fork خودتون `git clone` کنید. **ZIP دانلود نکنید**، چون برای BUG-4 تاریخچه‌ی git لازمه.
2. یه Branch بسازید: `git switch -c fix/<اسم-شما>`
3. برنامه و تست‌ها رو یه بار اجرا کنید (داخل پوشه‌ی زبان):

| زبان | پوشه | اجرای گزارش | همه‌ی تست‌ها |
|---|---|---|---|
| Python 3.9+ | `python/` | `python report.py ../data/orders.csv` | `python -m unittest -v` |
| Java 17+ و Maven | `java/` | `mvn -q compile` و بعد `java -cp target/classes labshop.Report ../data/orders.csv` | `mvn test` |
| .NET 8+ | `csharp/` | `dotnet run --project LabShop -- ../data/orders.csv` | `dotnet test` |
| Go 1.21+ | `go/` | `go run . ../data/orders.csv` | `go test ./...` |

توی IDE همون پوشه رو باز کنید (برای C# فایل `csharp/LabShop.sln`)، آرگومان برنامه رو `../data/orders.csv` بذارید و Working Directory رو پوشه‌ی زبان.

یکی از تست‌ها از همین اول قرمزه. این عمدیه (BUG-4).

## قواعد قیمت‌گذاری

درستی خروجی رو با این قواعد بسنجید، نه با کد. همه‌ی مبالغ به تومان و عدد صحیح‌ان.

1. مبلغ هر ردیف = `unit_price × qty`. **subtotal** = جمع ردیف‌های سفارش.
2. **تخفیف عمده:** اگه از یه کالا (SKU یکسان) توی یه سفارش در مجموع ۱۰ عدد یا بیشتر خریده بشه، مبلغ اون کالا ۱۰٪ تخفیف می‌گیره.
3. **کوپن** روی مبلغ بعد از تخفیف عمده حساب می‌شه:
   - `OFF10`: ۱۰٪، `OFF20`: ۲۰٪
   - `FIX50`: ۵۰٬۰۰۰ تومان (نه بیشتر از خود مبلغ)
   - کوچیک یا بزرگ بودن حروف و فاصله‌ی اول و آخر کد مهم نیست.
   - کد ناشناخته نادیده گرفته می‌شه (بدون تخفیف) و توی خط `invalid coupons` شمرده می‌شه.
4. **discount** = تخفیف عمده + تخفیف کوپن. **مبلغ مشمول مالیات** = subtotal − discount.
5. **مالیات (tax):** ۹٪ مبلغ مشمول مالیات، گرد به نزدیک‌ترین تومان (۰٫۵ به بالا).
6. **هزینه‌ی ارسال (shipping):** اگه مبلغ مشمول مالیات ۱٬۰۰۰٬۰۰۰ یا بیشتر باشه رایگانه، وگرنه ۴۰٬۰۰۰.
7. **total** = مبلغ مشمول مالیات + tax + shipping. **grand total** = جمع total همه‌ی سفارش‌ها.

قالب `data/orders.csv`: هر خط `id,customer,coupon,items` است و `items` چند تا `SKU:unit_price:qty` که با `|` جدا شدن.

## گزارش‌های باگ

به ترتیب جلو برید. BUG-1 برنامه رو متوقف می‌کنه و تا رفع نشه بقیه دیده نمی‌شن.

### BUG-1: برنامه وسط گزارش می‌ترکه
> «گزارش امشب نصفه چاپ شد و برنامه با خطا بسته شد.»

**ابزار: Stack Trace.** پیدا کنید کدوم خط از کد خودمون با چه داده‌ای خطا داده، و بپرسید چرا اون مقدار اونجا بود. فقط جلوی خطا رو نگیرید: خروجی باید با قاعده‌ی ۳ هم بخونه.

### BUG-2: شکایت مشتری سفارش 1047
> «دوازده تا K07 خریدم ولی تخفیف عمده نگرفتم.»

الان total سفارش 1047 برابر `557739` چاپ می‌شه، ولی باید `507381` باشه.

**ابزار: Breakpoint شرطی.** Breakpoint رو توی تابع قیمت‌گذاری بذارید با شرط «شناسه‌ی سفارش برابر 1047» و متغیرها رو Watch کنید.

**برای این باگ اول تست بازتولید بنویسید:** تست رو اجرا کنید، قرمز بودنش رو ببینید و Commit کنید. بعد رفع کنید تا سبز بشه.

### BUG-4: مالیات بعضی سفارش‌ها ۱ تومان کمه
> «از چند روز پیش مالیات بعضی سفارش‌ها یه تومن کمتر از ماشین‌حساب ماست. نسخه‌ی v1.0 درست بود.»

**ابزار: `git bisect`.** پیدا کنید کدوم Commit این باگ رو آورده. تست مالیات (`TaxTest`) همین باگ رو نشون می‌ده، پس تست جدید لازم نیست.

1. تغییرهاتون رو Commit کنید (bisect با تغییرهای Commit‌نشده کار نمی‌کنه).
2. از **ریشه‌ی ریپو** (نه پوشه‌ی زبان) اجرا کنید:
   ```bash
   git bisect start main v1.0
   git bisect run <دستور تست مالیات از جدول زیر>
   git bisect reset
   ```

| زبان | دستور تست مالیات (از ریشه‌ی ریپو) |
|---|---|
| Python | `python -m unittest discover -s python -k TaxTest` |
| Java | `mvn -q -f java/pom.xml test -Dtest=TaxTest` |
| C# | `dotnet test csharp/LabShop.sln --filter TaxTests` |
| Go | `go -C go test ./pricing -run TestTax` |

اگه bisect یه Commit بی‌ربط رو مقصر دونست، دستور رو روی `v1.0` امتحان کنید: باید سبز باشه. اگه `git bisect run` توی PowerShell کار نکرد، از Git Bash استفاده کنید.

### BUG-3 (اختیاری): grand total با جمع ستون total نمی‌خونه
> «حسابداری می‌گه عدد آخر گزارش با جمع ستون total فرق داره. هر خط رو جدا چک کردیم و درست بود.»

**ابزار: Watch و Step Into.** جایی که grand total حساب می‌شه Breakpoint بذارید و نتیجه‌ی یه سفارش رو با خط چاپ‌شده‌ی همون سفارش مقایسه کنید. سفارش‌هایی که فرق دارن چه وجه مشترکی دارن؟

## تحویل

1. برای هر باگ یه Commit رفع با پیامی مثل `fix: ... (BUG-1)`. برای BUG-2 قبلش Commit تست قرمز.
2. جدول `ANSWERS.md` رو پر کنید: برای هر باگ یه خط.
3. خودتون چک کنید (Git Bash، داخل پوشه‌ی زبان):
   ```bash
   python report.py ../data/orders.csv > out.txt   # یا دستور اجرای زبان خودتون
   git diff --no-index --ignore-cr-at-eol ../expected-output.txt out.txt
   ```
   اگه BUG-3 رو رفع نکردید، فقط خط `grand total` باید فرق داشته باشه.
4. Branch رو به Fork خودتون Push کنید و لینکش رو **تا آخر کلاس** به دستیار آموزشی بدید.
