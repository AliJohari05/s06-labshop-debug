# تمرین سر کلاس جلسه‌ی ۶: دیباگ گزارش فروش LabShop

LabShop یه فروشگاه اینترنتی کوچیکه. هر شب یه برنامه سفارش‌های روز رو از `data/orders.csv` می‌خونه و گزارش فروش چاپ می‌کنه. همین برنامه به چهار زبان نوشته شده (`python/`، `java/`، `csharp/`، `go/`) و هر چهار نسخه دقیقاً یه رفتار و یه باگ‌ها رو دارن.

**یکی از زبان‌ها رو انتخاب کنید** (بهتره زبان سرویس تیمتون) و فقط با همون کار کنید.

چهار گزارش باگ رسیده. برای هر کدوم باید علت ریشه‌ای رو پیدا و رفع کنید. زمان: حدود یک ساعت.

---

## شروع

1. بالای صفحه **Fork** کنید تا یه کپی تو اکانت خودتون داشته باشید.
2. از Fork خودتون `git clone` کنید. **ZIP دانلود نکنید**، چون برای باگ ۴ تاریخچه‌ی git لازمه.
3. یه Branch بسازید: `git switch -c fix/<اسم-شما>`
4. برنامه و تست‌ها رو یه بار اجرا کنید:

| زبان | پوشه | اجرای گزارش | همه‌ی تست‌ها | پیش‌نیاز |
|---|---|---|---|---|
| Python | `python/` | `python report.py ../data/orders.csv` | `python -m unittest -v` | Python 3.9+ |
| Java | `java/` | `mvn -q compile` و بعد `java -cp target/classes labshop.Report ../data/orders.csv` | `mvn test` | JDK 17+ و Maven |
| C# | `csharp/` | `dotnet run --project LabShop -- ../data/orders.csv` | `dotnet test` | .NET 8+ |
| Go | `go/` | `go run . ../data/orders.csv` | `go test ./...` | Go 1.21+ |

دستورها رو داخل پوشه‌ی زبان اجرا کنید. توی IDE هم همون پوشه رو باز کنید (برای C# فایل `csharp/LabShop.sln`) و در Run Configuration آرگومان برنامه رو `../data/orders.csv` بذارید و Working Directory رو پوشه‌ی زبان.

یکی از تست‌ها از همین اول قرمزه. این عمدیه.

---

## قواعد قیمت‌گذاری

درستی خروجی رو با این قواعد بسنجید، نه با کد. همه‌ی مبالغ به تومان و عدد صحیح‌ان.

1. مبلغ هر ردیف = `unit_price × qty`. **subtotal** = جمع ردیف‌های سفارش.
2. **تخفیف عمده:** اگه از یه کالا (SKU یکسان) توی یه سفارش در مجموع ۱۰ عدد یا بیشتر خریده بشه، مبلغ اون کالا ۱۰٪ تخفیف می‌گیره.
3. **کوپن** روی مبلغ بعد از تخفیف عمده حساب می‌شه:
   - `OFF10`: ۱۰٪، `OFF20`: ۲۰٪
   - `FIX50`: ۵۰٬۰۰۰ تومان (نه بیشتر از خود مبلغ)
   - کوچیک یا بزرگ بودن حروف و فاصله‌ی اول و آخر کد مهم نیست.
   - کد ناشناخته نادیده گرفته می‌شه (بدون تخفیف) و توی خط `invalid coupons` شمرده می‌شه.
4. **discount** = تخفیف عمده + تخفیف کوپن. **مبلغ مشمول مالیات** = subtotal − discount.
5. **مالیات (tax):** ۹٪ مبلغ مشمول مالیات، گرد به نزدیک‌ترین تومان (۰٫۵ به بالا).
6. **هزینه‌ی ارسال (shipping):** اگه مبلغ مشمول مالیات ۱٬۰۰۰٬۰۰۰ یا بیشتر باشه رایگانه، وگرنه ۴۰٬۰۰۰.
7. **total** = مبلغ مشمول مالیات + tax + shipping. **grand total** = جمع total همه‌ی سفارش‌ها.

قالب `data/orders.csv`: هر خط `id,customer,coupon,items` است و `items` چند تا `SKU:unit_price:qty` که با `|` جدا شدن.

## گزارش‌های باگ

برای هر باگ این ترتیب رو رعایت کنید: **بازتولید ← تست قرمز ← فرضیه ← آزمایش با ابزار ← علت ریشه‌ای ← رفع ← تست سبز.** قبل از اینکه تست بازتولید داشته باشید، کد رو عوض نکنید.

### BUG-1: برنامه وسط گزارش می‌ترکه
> «گزارش امشب نصفه چاپ شد و برنامه با خطا بسته شد.»

**ابزار: Stack Trace.** پیدا کنید کدوم خط از کد خودمون با چه داده‌ای خطا داده، و بعد بپرسید چرا اون مقدار اونجا بود. فقط جلوی خطا رو نگیرید: خروجی باید با قاعده‌ی ۳ هم بخونه.

### BUG-2: شکایت مشتری سفارش 1047
> «دوازده تا K07 خریدم ولی تخفیف عمده نگرفتم.»

الان total سفارش 1047 برابر `557739` چاپ می‌شه، ولی باید `507381` باشه.

**ابزار: Breakpoint شرطی.** ۸۰ تا سفارش داریم. Breakpoint رو توی تابع قیمت‌گذاری بذارید با شرط «شناسه‌ی سفارش برابر 1047»، قدم‌به‌قدم جلو برید و متغیرها رو Watch کنید.

### BUG-3: grand total با جمع ستون total نمی‌خونه
> «حسابداری می‌گه عدد آخر گزارش با جمع ستون total فرق داره. هر خط رو جدا چک کردیم و درست بود.»

**ابزار: Watch و Step Into.** یه Breakpoint جایی بذارید که grand total حساب می‌شه، و نتیجه‌ی یکی از سفارش‌ها رو با خطی که برای همون سفارش چاپ شده مقایسه کنید. سفارش‌هایی که فرق دارن چه وجه مشترکی دارن؟

### BUG-4: مالیات بعضی سفارش‌ها ۱ تومان کمه
> «از چند روز پیش مالیات بعضی سفارش‌ها یه تومن کمتر از ماشین‌حساب ماست. نسخه‌ی v1.0 درست بود.»

**ابزار: `git bisect`.** باید پیدا کنید کدوم Commit این باگ رو آورده. تست‌های مالیات (`TaxTest`) همین باگ رو نشون می‌دن.

`git bisect run` دستور رو همیشه از **ریشه‌ی ریپو** اجرا می‌کنه، نه از پوشه‌ای که توش هستید. برای همین دستورهای زیر از ریشه نوشته شدن:

| زبان | دستور تست مالیات (از ریشه‌ی ریپو) |
|---|---|
| Python | `python -m unittest discover -s python -k TaxTest` |
| Java | `mvn -q -f java/pom.xml test -Dtest=TaxTest` |
| C# | `dotnet test csharp/LabShop.sln --filter TaxTests` |
| Go | `go -C go test ./pricing -run TestTax` |

1. تغییرهاتون رو Commit کنید، چون bisect با تغییرهای Commit‌نشده کار نمی‌کنه.
2. دستور تست رو یه بار دستی روی `v1.0` امتحان کنید (`git checkout v1.0`، اجرا، `git switch -`). باید **سبز** باشه. اگه دستور روی Commit خوب هم قرمز بشه، bisect جواب غلط می‌ده.
3. از ریشه‌ی ریپو:
   ```bash
   git bisect start main v1.0
   git bisect run <دستور تست مالیات>
   git bisect reset
   ```

اگه وقت دارید، یه بار هم بدون `run` و با `git bisect good` / `git bisect bad` دستی جلو برید تا ببینید `run` دقیقاً چه کاری رو خودکار می‌کنه. اگه `git bisect run` توی PowerShell درست کار نکرد، از Git Bash استفاده کنید.

## تحویل

- برای BUG-1 تا BUG-3 یه **تست بازتولید** بنویسید که قبل از رفع قرمز و بعدش سبز باشه. برای BUG-4 تست موجود کافیه.
- رفع هر باگ یه Commit جدا با پیامی مثل `fix: ... (BUG-2)`.
- فایل `ANSWERS.md` رو پر کنید.
- در آخر **همه‌ی تست‌ها سبز** باشن و خروجی گزارش **دقیقاً** با `expected-output.txt` یکی باشه. برای مقایسه (در Git Bash، داخل پوشه‌ی زبان):
  ```bash
  python report.py ../data/orders.csv > out.txt   # یا دستور اجرای زبان خودتون
  git diff --no-index --ignore-cr-at-eol ../expected-output.txt out.txt
  ```
  اگه چیزی چاپ نشد یعنی یکی‌ان.
- Branch رو به Fork خودتون Push کنید و لینکش رو به روشی که دستیار آموزشی می‌گه بفرستید.
